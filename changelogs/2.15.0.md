## [2.15.0](https://github.com/Kevin-Lee/logger-f/issues?q=is%3Aissue%20is%3Aclosed%20milestone%3Av2-m10) - 2026-11-23


## New Features

### Include the filename and line number in the log to indicate where it was written (#623)

logger-f now adds the source location of the log call to the log message. The compiler captures the location at the call site, so the location is the one in your code, not one inside logger-f.

```scala
import loggerf.syntax.all._

// in com.example.Foo.bar at line 42 of Foo.scala
log(fa)(a => info(s"Hello $a"))
```

logs

```
Hello 1 at com.example.Foo.bar(Foo.scala:42)
```

The location has this shape: `<enclosing class>.<enclosing method>(<file name>:<line>)`. It is the same shape as a JVM stack trace frame. logger-f stores only the file name, not the path, so the compiled class files do not change when you build the same source in a different directory.

All the message constructors (`debug`, `info`, `warn`, `error`, the `A` variants such as `debugA`, and the ones with a `Throwable`) capture the location. `log`, `log_`, `logS` and `logS_` send it to `CanLog`.

#### New `CanLog` methods

`CanLog` has new location-aware methods with a `loggerf.SourceLocation` parameter, e.g.

```scala
def info(sourceLocation: SourceLocation)(message: => String): Unit
def info(throwable: Throwable, sourceLocation: SourceLocation)(message: => String): Unit
```

They have default implementations which put the rendered location into the message and call the existing methods. So an existing custom `CanLog` gets the source location with no change. A custom `CanLog` can override them to use the location in a different way.

#### Remove the source location

If you do not want the source location in the log message, use `withoutSourceLocation`.

```scala
import loggerf.logger._

implicit val canLog: CanLog = Slf4JLogger.slf4JCanLog[MyApp].withoutSourceLocation
```

#### `logger-f-test-kit`

`CanLog4Testing` records the source locations in `sourceLocations: Vector[(Int, SourceLocation)]`. The index is the same as the index in `messages`. `sourceLocations` is not part of the equality of `CanLog4Testing`, so the existing tests do not change.

#### `logger-f-doobie1`

`LoggerFLogHandler` logs without a source location because the logs inside doobie's `LogHandler` have no call site in your code.

#### Note

`LeveledMessage` has a new field, `sourceLocation`. If your code creates or pattern matches `LeveledMessage` directly, you must change it.


### Let users choose where and how the source location appears in the log message (#705)

`loggerf.logger.SourceLocationFormat` tells where the source location goes and what text goes around it.

The rendered location is `prefix + location + suffix`. It goes before or after the message. logger-f adds no other text, so an empty `prefix` or `suffix` adds nothing.

```scala
import loggerf.logger.SourceLocationFormat

SourceLocationFormat.default
// Hello at com.example.Foo.bar(Foo.scala:42)

SourceLocationFormat.beforeMessage("[", "] ")
// [com.example.Foo.bar(Foo.scala:42)] Hello

SourceLocationFormat.afterMessage(" (", ")")
// Hello (com.example.Foo.bar(Foo.scala:42))
```

If you do not set a format, logger-f uses `SourceLocationFormat.default` (`afterMessage(" at ", "")`).

#### Set the format with each backend

Each backend has new factory methods which take a `SourceLocationFormat`.

slf4j (`logger-f-slf4j`)

```scala
Slf4JLogger.slf4JCanLogWithSourceLocationFormat[MyApp](sourceLocationFormat)
Slf4JLogger.slf4JCanLogWithSourceLocationFormat("my-logger-name", sourceLocationFormat)
Slf4JLogger.slf4JCanLogWithLoggerAndSourceLocationFormat(logger, sourceLocationFormat)
```

log4s (`logger-f-log4s`)

```scala
Log4sLogger.log4sCanLogWithSourceLocationFormat[MyApp](sourceLocationFormat)
Log4sLogger.log4sCanLogWithSourceLocationFormat("my-logger-name", sourceLocationFormat)
Log4sLogger.log4sCanLogWithLoggerAndSourceLocationFormat(logger, sourceLocationFormat)
```

log4j (`logger-f-log4j`)

```scala
Log4jLogger.log4jCanLogWithSourceLocationFormat[MyApp](sourceLocationFormat)
Log4jLogger.log4jCanLogWithSourceLocationFormat("my-logger-name", sourceLocationFormat)
Log4jLogger.log4jCanLogWithLoggerAndSourceLocationFormat(logger, sourceLocationFormat)
```

sbt logging (`logger-f-sbt-logging`)

```scala
SbtLogger.sbtLoggerCanLogWithSourceLocationFormat(sourceLocationFormat)
```

e.g.)

```scala
import loggerf.logger._

implicit val canLog: CanLog =
  Slf4JLogger.slf4JCanLogWithSourceLocationFormat[MyApp](SourceLocationFormat.beforeMessage("[", "] "))
```

The existing factory methods and constructors still compile and work with no change. They use `SourceLocationFormat.default`.

A custom `CanLog` can override `def sourceLocationFormat: SourceLocationFormat` to set its own format.
